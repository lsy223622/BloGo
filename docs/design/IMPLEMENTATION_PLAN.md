# Go 极简混合渲染博客：工程实施计划

-   文档版本：1.2
-   适用范围：V1
-   配套规范：[`DESIGN.md`](DESIGN.md)
-   状态：全部 26 项任务完成；Gate A 至 Gate E 本地验收通过

## 1. 使用方式

本文件负责任务顺序、依赖关系、交付物和验收。所有行为契约以 `DESIGN.md`
为准。

每个任务完成后必须： 1. 检查任务范围没有扩张。 2. 添加或更新自动化测试。
3. 运行相关测试及 `go test ./...`、`go vet ./...`。 4.
更新与实现行为有关的文档。 5.
汇报修改文件、测试结果、已知问题和未完成项。

不要一次性要求 Agent
实现全部任务。下文章节按职责分组，实际执行遵循任务依赖和 Gate；从最小端到端站点开始逐步验收。未获得明确授权，不自动部署到生产环境、修改服务器权限或重载
Nginx。

## 3. 通用完成规则

-   只实现当前任务及其必要依赖，不顺手添加管理后台、插件、登录、搜索或内容数据库。
-   不引入没有实际用途的接口层、工厂、依赖注入容器或通用扩展机制。
-   确定性内容错误必须明确失败；不能以警告代替关键校验。
-   构建任务不得修改当前线上版本，直到完整构建和校验成功。
-   测试不得依赖外网可用性；外部链接检查不是默认生产构建门槛。
-   测试夹具应覆盖
    Public、Unlisted、Draft、多级分类、标签、日期边界、特殊
    HTML、代码和数学公式。
-   同时覆盖无日期独立页面、Unicode 分类标签展示名、系统页面与分页身份、导航来源和当前页面的区分。
-   从 REN-01 开始保留最小渲染夹具；BLD-02 提供可执行的端到端静态构建；INT-01 扩大覆盖，不到最后才首次串联各模块。
-   生产发布及权限集成检查在 Linux 本地文件系统执行；Windows 验证解析、构建、统计和预览。
-   修改 `DESIGN.md`
    中定义的契约时，必须在同一变更中更新测试、相关任务说明和受影响的调用方。

## 4. 阶段一：项目基础与内容模型

### FND-01 --- 项目骨架

**前置条件：** 无。

**实现范围：** - 初始化 Go Module 和 `cmd/blog`。 - 建立
`internal/config`、`content`、`markdown`、`site`、`render`、`build`、`preview`、`stats`
包目录。 - 实现 `build`、`publish`、`watch`、`dev`、`stats`、`report` 的命令路由与统一错误退出约定，语义遵守设计第 6 节。

**交付物：** - 可编译的最小程序。 - `--help` / 子命令帮助。 -
基础测试结构。

**验收：** - `go test ./...`、`go vet ./...` 通过。 -
未实现的子命令明确返回非成功状态。 - 不引入大型 Web 框架。

### FND-02 --- 配置与路径校验

**前置条件：** FND-01。

**实现范围：** - 按 `DESIGN.md` 第 6 节解析 YAML 配置。 -
按命令校验必需字段和访问条件，为错误提供明确位置。 - 将相对路径解析为相对于配置文件的路径。 - 校验时区、站点 origin、回环 IP 与端口、正整数参数和目录重叠。 - 验证统计数据库、密钥和私有报告不会落入公开输出目录，发布相关目录满足同文件系统要求。 - 固定设计中的默认值、拒绝重复和未知键，保留 `extra` 映射。

**交付物：** - 配置结构、示例配置和配置校验测试。

**验收：** - 错误配置在任何构建或服务启动前失败。 -
不依赖当前工作目录。 - 目录冲突、非法 URL 和无效时区均有测试。 - 静态构建和预览无需统计配置或密钥，stats / report 无需读取内容源。 - `build --output` 使用独立输出目录。

### CNT-01 --- Front Matter 与源文件解析

**前置条件：** FND-02。

**实现范围：** - 解析 `content/posts/` 中的 Markdown。 - 解析
`content/pages/` 中的 Markdown 与带 Front Matter 的 HTML。 - 建立
`ContentItem`。 - 保留正文原文，不在解析阶段执行模板或脚本。

**交付物：** - 内容解析函数、逻辑模型、测试夹具。

**验收：** - YAML 与正文正确分离。 - 支持多层源目录。 -
错误包含文件相对路径和字段位置（可得时）。 -
不支持的文件类型不会被静默发布。

### CNT-02 --- 身份、slug 与 URL

**前置条件：** CNT-01。

**实现范围：** - 按设计规则解析 `id`、`slug`、`permalink`、`aliases`。 -
生成命名空间内容 ID。 - 固定 ASCII ID / slug 语法、缺省 slug 算法、文章与嵌套独立页面默认 URL。 - 规范化尾斜杠、URL 到 index.html 的映射并检查保留路由、aliases 及输出冲突。

**交付物：** - 身份和 URL 解析逻辑。 - 覆盖边界条件的测试。

**验收：** - 显式 ID 在 slug 变化后稳定。 - 缺少 ID 时使用 slug。 -
标题修改不会覆盖显式 slug。 - 重复 URL、路径穿越、query/fragment
和非法路径均被拒绝。 - `/about` 与 `/about/` 解析为同一规范路由，`.html` 规范 permalink 被拒绝。 - 页面目录与输出文件冲突、保留路径和不合法 ID 有测试。

### CNT-03 --- 状态与元数据校验

**前置条件：** CNT-02。

**实现范围：** - 实现 Public、Unlisted、Draft。 -
实现文章必需日期、独立页面可选日期和站点时区规则。 - 实现布局默认值及合法源文件组合、`stats` 与 `extra` 类型校验。 - 解析 `taxonomies.yaml` 的版本、稳定 ID、Unicode 展示名和 parent 关系，验证内容引用。 - 默认状态为 Draft。

**交付物：** - 统一校验入口。 - 状态规则和日期规则测试。

**验收：** - Public / Unlisted 文章必须有有效发布日期。 - 存在 `published` 时，`updated` 缺省等于它；独立页面可无日期或仅有 `updated`。 - 文件系统时间不影响内容时间。 - Draft 不进入生产索引。 - 无效日期关系和无效状态会导致确定性错误。 - 展示名的中文、大小写、标点和 emoji 保留；未知分类标签、非法稳定 ID、重复键与父分类环失败。

### CNT-04 --- Markdown、摘要与目录

**前置条件：** CNT-01；可与 CNT-02 / CNT-03 的非冲突工作并行。

**实现范围：** - 接入 Goldmark。 - 用真实样例确认 V1 支持的扩展。 - 生成
HTML、摘要、标题锚点和目录数据。 - 记录 Markdown 支持说明。

**交付物：** - `internal/markdown` 实现。 -
`docs/markdown-support.md`。 - Markdown 回归样例。

**验收：** - 手写摘要优先。 - 自动摘要从 AST 提取，不使用简单正则删除
HTML。 - 摘要排除代码、脚本、样式和数学公式。 - 原生 HTML 按设计保留。 -
锚点和摘要对同一输入保持稳定。

## 5. 阶段二：索引与页面数据

### IDX-01 --- SiteIndex

**前置条件：** CNT-03。

**实现范围：** - 建立
`ByID`、`ByURL`、`ByPublished`、`ByUpdated`、Public 文章集合及独立页面集合。 - 实现有目标日期优先、日期倒序、稳定 ID 升序的排序。

**交付物：** - `internal/site` 核心索引与单元测试。

**验收：** - 两种排序独立正确。 - 同时间文章按稳定 ID 打破平局。 - 修改
`updated` 不影响发布时间排序。 - Unlisted 和 Draft 不进入公共聚合。 - 无日期页面构建、重启后顺序按稳定 ID 保持一致。

### IDX-02 --- 分类、标签、归档与分页

**前置条件：** IDX-01。

**实现范围：** - 基于元数据 parent 生成分类及祖先聚合。 - 分类、标签总览和条目索引。 - 年月归档。 - 首页列表、分页、最近更新列表。 - 为每个系统页面和分页按设计第 11.2 节分配稳定页面 ID、kind 和规范路由。

**交付物：** - 聚合数据结构和路由数据。

**验收：** - 公共聚合只包含 Public 文章。 - 分页没有重复或遗漏。 -
分类、标签、归档 URL 唯一。 - 分类及祖先聚合按文章 ID 去重，未被 Public 内容使用的条目不进入总览。 - 展示名和父分类改变不改变条目 URL 或 ID。 - 空结果、边界页数及系统和分页 ID 冲突有测试。

### IDX-03 --- 导航、Feed、SEO 与重定向

**前置条件：** IDX-01、IDX-02。

**实现范围：** - 按发布时间计算上一篇/下一篇。 - 生成 RSS 2.0。 - 生成
Sitemap、robots.txt、canonical、Open Graph 数据。 - 校验 `aliases`
并导出 Nginx 重定向片段。

**交付物：** - Feed / SEO / 重定向生成逻辑。

**验收：** - Unlisted 不进入 Feed 和 Sitemap。 - canonical、分页和文章
URL 正确。 - 重定向循环、冲突和非法目标失败。 - 构建器不自动修改或重载
Nginx。 - canonical 与生成链接使用规范 URL；无尾斜杠及 index.html 以 301 跳转到目录 URL，保留 query；不存在的 URL 仍返回 404。

## 6. 阶段三：模板与前端

### REN-01 --- 模板与页面布局

**前置条件：** IDX-03、CNT-04。

**实现范围：** - 使用 `html/template`
实现文章、独立页面、首页、分类、标签、归档、分页和 404。 - 支持
`article`、`page`、`standalone`。 - 正确处理可信 Markdown HTML
和普通元数据转义。 - 默认主题遵循设计第 8.5 节的 Jasmine 视觉约定。

**交付物：** - 模板目录和渲染入口。

**验收：** - 输出为完整 HTML。 - Standalone
页面不被额外套入普通文章模板。 - 普通元数据保持上下文转义。 - 自定义
HTML 页面可以控制 DOM 与样式。

-   建立 Public、Unlisted、无日期独立页面的最小渲染样例，后续任务复用；Standalone 的 `noindex` 校验与原文保留符合设计。

### REN-02 --- 阅读体验

**前置条件：** REN-01。

**实现范围：** - 响应式布局、深浅色模式。 - 代码高亮、目录、锚点。 -
图片灯箱、数学公式。 - 友情链接和侧边栏。

**交付物：** - 前端 CSS / JS 和相应模板。 - 首页、文章、分类标签、归档和友链的桌面/手机、浅色/深色截图或人工检查记录，对照 Jasmine 参考布局与配色。

**验收：** - 移动端和桌面端可用。 - 禁用 JavaScript
后正文和基本导航仍可用。 - 不依赖第三方 CDN 才能阅读核心内容。 -
特殊页面的脚本和样式不会被意外破坏。 - KaTeX 如使用客户端渲染，自托管所需资源，禁用 JS 时保留可读公式源码。

### REN-03 --- 静态资源与缓存

**前置条件：** REN-01。

**实现范围：** - 复制 `static/`。 - 压缩构建器管理的 CSS / JS 和适合处理的普通模板输出。 - 为构建器管理的长期缓存资源生成内容哈希名称。 - 校验生成的资源引用。 - 作者显式引用的资源路径保持可用，HTML 片段、Standalone、内联脚本与样式保留原文。

**交付物：** - 资源处理逻辑和输出清单。

**验收：** - 每个生成资源引用都指向存在文件。 -
资源内容变化时名称变化。 - 不覆盖源资源。 - static 不覆盖生成的页面或系统输出，也不占用 API 和统计服务映射。 - 不通过全站字符串替换破坏特殊页面。

## 7. 阶段四：构建与发布

### BLD-01 --- 指纹扫描与输入快照

**前置条件：** REN-03。

**实现范围：** - 对允许的内容、模板、配置、分类标签元数据、静态资源和构建版本及选项计算确定性指纹。 -
创建独立输入快照。 - 拒绝不允许的符号链接、特殊文件和目录越界。

**交付物：** - 扫描器、快照器、指纹测试。

**验收：** - 新建、修改、删除均能被发现。 -
修改文件内容即使时间戳不变也能检测到。 -
构建输出和统计文件不触发扫描。 - 快照指纹与扫描指纹不一致时拒绝构建。

### BLD-02 --- 完整构建与校验

**前置条件：** BLD-01。

**实现范围：** - 实现 `blog build --output <dir>`，从快照解析内容、建立索引、渲染所有页面。 -
生成静态资源、Feed、Sitemap、`meta/manifest.json` 和指纹文件，输出为 public/ 与 meta/。 -
检查路径、URL、内部链接、资源与可见性规则。

**交付物：** - 一次完整的独立输出构建。 - 最小端到端站点及可执行构建检查。

**验收：** - 设计第 10.4 节要求的错误导致构建失败，缺失内部内容链接默认警告、开启 strict_links 时失败。 - 失败不修改当前版本。 - Draft
不在生产输出中。 - 删除的源文件不会残留于新版本。 -
同一快照生成相同的页面集合和排序。 - 从源文件到 HTML、Feed 和 Manifest 的最小链路在本任务验证，静态构建不依赖运行中的统计服务。

### BLD-03 --- Manifest 与原子发布

**前置条件：** BLD-02。

**实现范围：** - 校验 BLD-02 生成的 Manifest 与指纹。 - 将网站与 Manifest 放入同一 release。 - 实现 `blog publish`、Linux 上 `current` 符号链接原子切换与进程间发布锁。 - 按 `build.keep_releases` 保留完整版本用于回滚，成功发布后清理。

**交付物：** - 可发布的完整版本目录。 - 发布与失败恢复逻辑。

**验收：** - Manifest 与静态站点版本一致。 - 切换失败时旧版本仍可用。 -
Nginx 不会读取暂存目录。 - 私有文件和源码不进入公开目录。 - 每个 HTML 页面恰好有一个 Manifest 条目，日期缺省、统计开关、系统和分页身份正确。 - 并发 publish / watch 对同一目标明确失败。 - 清理保留当前版本，人工回滚可恢复站点和 Manifest。

### BLD-04 --- Watcher 自动扫描

**前置条件：** BLD-03。

**实现范围：** - 默认每 60 秒扫描。 - 输入变化时串行触发完整构建。 -
记录最后成功快照指纹和错误状态。 - 使用与 publish 相同的发布锁。

**交付物：** - `blog watch`。

**验收：** - 无变化不构建。 - 构建期间源变化会在下一轮扫描发现，当前构建只读取校验过的快照。 -
不会并发发布两个版本。 - 服务重启后识别当前版本。 -
内容错误按失败指纹抑制重复日志，源变化后重新尝试；I/O、磁盘和发布等暂时性错误下一轮可重试，同类日志限频。 - 可通过手动 publish 对相同输入重新构建。

### BLD-05 --- 本地预览

**前置条件：** BLD-03。

**实现范围：** - `blog dev`。 - 本地 HTTP 预览。 -
内容或模板变化后重建并刷新浏览器。 - 支持 Draft 本地预览。

**交付物：** - 本地预览服务器和开发说明。

**验收：** - 默认只监听回环地址。 - 草稿不会进入生产输出。 -
不修改生产当前版本。 - 独立开发目录无需生产符号链接，规范 URL 跳转与生产一致。

### BLD-06 --- 部署配置与文档

**前置条件：** BLD-04。

**实现范围：** - Nginx 示例配置。 - systemd service / timer 示例。 -
用户、组、目录权限。 - Linux 本地文件系统、发布版本清理与回滚流程。 - HTML 重新验证、哈希资源长期缓存的配置。 -
手动应用重定向片段的说明。

**交付物：** - `deploy/` 示例和部署文档。

**验收：** - 所有进程非 root 运行。 - 构建器不持有 Git 凭据。 -
统计服务无源文件读取权限。 - Nginx 无权读取统计数据库和私有报告。 -
配置中明确标出需要管理员操作的步骤。 - 实测无尾斜杠和 index.html 的 301、query 保留、404 状态及回滚流程。

## 8. 阶段五：统计系统

### STA-01 --- SQLite 数据层

**前置条件：** FND-02。

**实现范围：** - 实现 `DESIGN.md` 第 13 节五张表及索引。 -
数据库初始化、schema 版本、短事务和清理。 - 持久化访客 HMAC 密钥。 - 验证并锁定 `modernc.org/sqlite` 版本，配置 WAL、单写连接及每连接 5 秒 busy timeout。 - 来源按 day、page_id、source 聚合，支持全站和逐页来源查询。

**交付物：** - `internal/stats` 数据访问逻辑。 - 数据库和事务测试。

**验收：** - 重复事件不重复计数。 - 同日访客只增加一次 UV。 -
任何事务失败都不产生部分更新。 - 清理过期去重记录不删除聚合统计。 -
服务重启后密钥和历史数据保持稳定。 - 并发重复事件只计数一次；锁竞争、超时和数据库只读故障不产生部分更新。 - 同一来源访问不同页面可分别统计；报告短读事务不阻塞正常采集。

### STA-02 --- 事件 API

**前置条件：** STA-01、BLD-03。

**实现范围：** - `POST /api/events`。 - 请求体限制、JSON 校验、Manifest
校验、去重与限流。 - 区分 `referrer_host` 与当前 `page_id`，HTTP Referer 仅辅助检查请求上下文。 - 明确 HTTP 状态码。

**交付物：** - HTTP handler 和 API 测试。

**验收：** - 未知页面 ID、非法字段和超大请求被拒绝。 -
重复事件不重复计数。 - 不支持任意文件访问、SQL 或内容修改。 - 只监听
loopback。 - 数据库故障时返回受控错误。 - 系统、分类标签、归档和分页均可独立上报，禁用统计的页面被拒绝。 - 请求 Referer 缺失不误拒有效事件，也不将它作为导航来源。 - 来源主机名、空值、畸形 URL、未知字段和类型有测试。

### STA-03 --- 浏览器采集脚本

**前置条件：** STA-02。

**实现范围：** - 每次页面加载生成 `event_id`。 - `localStorage` 保存每日
`visitor_id`。 - 日期按站点时区轮换。 - 使用 `sendBeacon` 发送 JSON。 -
将页面 ID 注入普通模板与 Standalone 页面。

-   从 `document.referrer` 仅提取主机名作为 `referrer_host`；当前页面只提交注入的稳定 ID。所有默认启用统计的 HTML 页面接入同一采集脚本。
-   页面首次可见时上报一次；入队失败时有限重试，复用事件 ID；Standalone 按 tokenizer 定位插入点，尊重 `stats: false`。

**交付物：** - 自托管统计脚本和页面接入逻辑。

**验收：** - 每次页面加载只产生一次逻辑事件。 - 重试复用同一事件 ID。 -
无存储权限时能够退化运行。 - 不收集完整 URL、指纹或无关信息。 -
统计失败不影响正文。 - 外部来源、站内来源和直接访问分开记录，当前页面归属正确。 - 脚本或注释中的伪 `</body>` 不会被当作插入点。 - 缺少合法插入点且启用统计的 Standalone 构建失败。

### STA-04 --- 聚合与报告

**前置条件：** STA-01、BLD-03。

**实现范围：** - 计算累计 PV、每日趋势、UV、来源和热门页面。 - 生成公开
`stats.json`。 - 生成私有 `report.html`，包括页面来源分布。 - 使用报告目标排他锁，基于单份 Manifest 和短数据库读事务生成；写前核对 build_id，分别原子替换输出。 - 只读业务数据，按 SQLite 规则处理辅助文件权限。

**交付物：** - 报告生成器和定时任务配置。

**验收：** - 新生成的公开 JSON 按本轮 Manifest 只包含 Public 页面，Unlisted 明细只写私有报告。 - pages 包含所有启用统计的 Public HTML 页面，热门文章只包含 post。 - 删除页面后历史数据保留并以 ID 标记已删除。 - 统计更新不触发博客构建。 - 私有报告不在 Nginx 公共路径中。 - Public / Unlisted 变更在下一次成功刷新后反映；失败保留旧输出，版本变化时放弃过期生成结果。 - 统计服务运行、停止和重启时报告均可读取数据库。

### STA-05 --- 统计部署与防滥用

**前置条件：** STA-02、STA-04、BLD-06。

**实现范围：** - Nginx 反向代理 `/api/events`。 - 精确映射
`/data/stats.json`。 - Nginx 请求大小和速率限制。 - systemd
配置、数据库备份和恢复文档。 - 验证数据库目录与 WAL / SHM 权限、报告只读连接，以及公开 JSON 的 no-cache 和 build_id。

**交付物：** - 统计部署示例和运维说明。

**验收：** - 公网无法直接连接统计服务端口。 - Nginx 只读公开统计
JSON。 - 数据库和私有报告不可通过 URL 读取。 -
统计服务停止不影响静态站点。 - 从备份恢复后可继续采集与报告。 - 报告定时任务失败后保留旧结果并可恢复刷新；辅助文件权限满足只读报告的启动和重启场景，不对活动数据库使用 immutable 模式。

## 9. 阶段六：集成、安全与交付

### INT-01 --- 端到端示例站点

**前置条件：** Gate C、Gate D 完成。

**交付物：** - 完整示例内容集：普通文章、缺省 ID、显式
ID、两种日期排序、无日期页面、多级分类、Unicode 标签、Unlisted、Draft、独立
HTML、图片、代码和公式。 - 扩展 BLD-02 已建立的端到端测试，覆盖系统页面、分页和逐页统计身份。

**验收：** - HTML、分类、归档、导航、Feed、Sitemap 和 Manifest
相互一致。 - 修改、增加、删除内容后重新构建结果正确。 - Unlisted 和
Draft 的可见性边界正确。 - 系统页面、分类和标签改名、分页以及 URL 规范化的 Manifest 身份一致。 - 从外部页面进入文章的导航来源与当前页 PV 对应正确。

### INT-02 --- 安全与权限验收

**前置条件：** BLD-06、STA-05。

**交付物：** - 路径穿越和符号链接测试。 - 构建失败和发布切换测试。 - API
滥用和数据库故障测试。 - 文件权限核查清单。

**验收：** - 构建器无法通过恶意路径读取预期目录外的文件。 -
统计服务无法读取 Markdown 源文件和 Git 凭据。 - Nginx
无法读取数据库与私有报告。 - 依据当前版本新生成的公开统计不包含 Unlisted 页面身份。 -
各组件故障相互隔离。 - 内容发布和报告刷新按各自契约运行；允许上次成功公开报告在刷新前暂时保留旧条目。

### INT-03 --- 文档、备份与恢复

**前置条件：** INT-01、INT-02。

**交付物：** - 配置说明。 - Markdown 支持说明。 -
本地预览、构建、发布和回滚说明。 - 统计指标与隐私说明。 - SQLite
备份和恢复流程。

-   设计、计划与实现一起纳入 Git 跟踪，文档引用使用实际的 `docs/design/` 路径。

**验收：** - 从干净环境能按文档完成构建。 -
能恢复内容源、发布站点和统计数据库。 - 关键命令和配置示例经实际验证。 -

## 10. 阶段验收门槛

### Gate A：内容模型

必须完成 FND-01、FND-02、CNT-01、CNT-02、CNT-03。

可以可靠解析内容和分类标签元数据，确定 ID、规范 URL、状态、布局默认值和可选日期语义；静态构建不被统计配置阻塞。

### Gate B：静态站点

必须完成 CNT-04、IDX-01 至 IDX-03、REN-01 至 REN-03、BLD-01 和 BLD-02。

可通过 `blog build --output <dir>` 从源文件生成完整、可阅读、可订阅的静态站点，并通过最小端到端验证。

### Gate C：自动发布

在 Gate B 基础上完成 BLD-03 至 BLD-06。

内容变化能够触发完整构建；构建失败不会破坏现有站点。

### Gate D：统计

必须完成 STA-01 至 STA-05。

采集、去重、聚合、公开 JSON 和私有报告正常工作，权限边界通过测试。

### Gate E：V1 交付

必须完成 INT-01 至 INT-03，并通过：

-   `go test ./...`
-   `go vet ./...`
-   端到端构建和发布测试
-   关键统计事务测试
-   私有文件与路径安全测试
-   备份恢复演练

任何 Gate 未通过，不进入下一阶段的生产部署。
