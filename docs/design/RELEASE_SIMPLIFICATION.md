# 首版发行与统一运行设计草案

日期：2026-10-25。状态：用户已确认完整方案并授权交给现有开发会话实施；实现完成后同步更新既有设计、配置与使用文档。

## 目的与已确定方向

让使用者下载发行包、解压、修改少量配置后启动博客，不需要 Go、Node、Python、数据库服务器，也不需要配置多个系统账户和定时器。

用户已选择统一服务：一个 `serve` 进程提供静态网页、采集接口、公开统计，并管理构建扫描、报告刷新和数据清理。默认监听 `127.0.0.1:25646`。反代负责域名和 TLS；systemd 只负责进程开机启动与异常重启。

用户要求把展示配置与运行配置分开，分类标签从运行配置中分离，支持受信任反代的真实客户端 IP，增加可关闭的逐事件详细统计，并为附件提供明确的内容输入位置。文章列表也显示阅读量。开源默认文件不能包含用户个人 Logo、联系方式或博文。

## 方案选择

考虑过保留 Nginx 直接读取发布文件，只合并后台服务。其改动较少，但仍需协调 Nginx root、API、JSON alias 和重定向规则，未解决部署复杂度。

已选择由 BloGo 统一处理网页和 API。反代只转发到一个上游。Go 继续读取构建好的静态文件，不在页面请求中执行 Markdown、模板构建或统计 SQL；浏览事件仍由浏览器单独发送。

构建、渲染和统计数据层复用已有实现。不得通过启动多个子进程来伪装单服务，不增加后台 CMS、插件或通用任务调度框架。

## 文件布局与所有权

```text
blogo/
  blog                         # Windows 预览包为 blog.exe
  config.yaml                  # 后端运行配置
  content/                     # 用户长期维护、需要备份的输入
    site.yaml                  # 展示配置、分类与标签
    posts/
    pages/
    assets/                    # 图片、附件、个人 Logo
  templates/                   # 随包默认模板
  static/                      # 随包 CSS/JS、字体、通用默认图标
  data/                        # 首次运行创建，整体私有
    releases/
    staging/
    current
    statistics/
    private/
  deploy/
    blogo.service
    nginx.conf.example
  docs/
```

`content/assets/a/b.png` 映射为 `/media/a/b.png`。`static/` 继续映射到网站根目录，保留受管资源 `/assets/` 的命名空间。路径冲突明确失败。公网页面处理器只提供当前发布版本的 public 文件及明确的公开统计端点，不能提供 data、配置、源码或私有报告的目录。

用户图片与个人 Logo 存在 content/assets，不放入随版本更新的默认资源目录。展示配置指定 Logo 和 favicon 路径，默认指向随包通用图标；个人站点可指向 `/media/brand/...`。

当前 6 张 Typecho 导入图片来自 `static/usr/uploads`。迁移个人试用数据时复制到 `content/assets/typecho/...` 并精确更新已知正文、HTML 和封面引用，逐文件核对摘要；不把生成的 public 作为输入。外部 URL 不批量下载或改写。旧图片 URL 的额外兼容不在本轮默认承诺中。

## 配置边界

主配置只放后端设置，示意：

```yaml
server:
  listen_addr: 127.0.0.1:25646
  base_url: http://127.0.0.1:25646
  trusted_proxies:
    - 127.0.0.1
    - "::1"
timezone: Asia/Shanghai
build:
  scan_interval: 60s
  keep_releases: 3
  strict_links: false
stats:
  enabled: true
  report_interval: 5m
  details:
    enabled: false
    retention: 168h
```

展示信息和分类标签合并到 `content/site.yaml`。该文件保存 schema_version、title、subtitle、language、page_size、summary_max_chars、Logo/favicon 路径及 profile，并以 categories、tags 映射保存分类标签，沿用已有稳定 ID、展示名和 parent 契约。字段按实际需要组织，不引入主题配置语言。当前独立 taxonomies.yaml 的数据在迁移时完整并入，不改变 ID 或内容引用。

默认数据路径由程序推导，常规配置不要求逐一填写 Manifest、数据库、密钥、公开和私有报告路径。路径仍须明确与输入分离；主配置和内容配置均严格验证，未知键、重复键和错误类型报错。所有文件中的相对输入路径以确定的站点根目录解析，不受进程当前目录偶然变化影响。

内容、site.yaml、附件、模板和静态资源变化触发构建；新构建失败保留上次成功版本。运行配置可在检查周期重读：扫描/报告间隔及详细统计开关、保留期生效不需修改 systemd；监听地址、base_url、timezone 和数据位置变化要求重启，避免构建与采集上下文混用。

## serve 生命周期

1. 校验配置、目录和监听地址，取得运行锁，拒绝第二实例使用同一运行数据。
2. 创建私有运行目录；校验已有数据库和密钥，不能把损坏数据静默重新初始化。
3. 首次无版本时构建并发布；已有有效版本时保留其可读性并检查输入变化。
4. 启用统计时初始化采集器和生成一份报告，然后开始对外服务。
5. 运行内容扫描、报告刷新和过期数据清理；任务串行或互斥，不允许长报告无限重叠。
6. 报告或后续构建失败记录错误并保留旧结果，下一轮重试。关闭进程时停止定时工作、完成或取消在途请求并关闭数据库。

只需要一个非 root 运行用户。快速试用可使用已有普通用户；长期运行提供一份 systemd service。不再要求默认安装多套用户组、统计 service 和 report timer。

HTTP 保留正式 404 状态、规范目录 URL、aliases、GET/HEAD、资源类型与缓存策略。历史 aliases 直接按当前发布数据生效，无需复制 Nginx 规则或重载。私有报告不挂到公网服务。`dev` 继续包含草稿，正式 serve 排除草稿；不能把含草稿的 Manifest 直接交给正式采集器。本地 dev 复用采集和公开报告路由以便试用，但草稿不采集，使用单独的 data/dev 数据，不能改写正式统计或把草稿身份加入正式清单。

首轮正式运行仍以 Linux 本地文件系统为目标，保留现有原子发布；Windows 包提供 dev/build。Windows 正式 serve 若要支持必须另有真实发布切换验收，不能只交叉编译后宣称支持。

## 可信代理与 IP

只在直接连接对端位于 trusted_proxies 时读取 X-Forwarded-For。默认模板仅列回环地址；跨机反代填写其实际 IP，不默认信任所有内网地址。

多值转发头按完整地址链从右向左解析，跳过已配置可信代理，取最近的不可信节点为客户端 IP。无有效转发值时使用连接对端；非可信对端的转发头不影响结果。IPv4、IPv6、非法值和伪造最左端地址必须有回归。

解析出的客户端 IP 用于按来源限流及可选详细记录。UV 仍使用每日访客标识的摘要，不改成 IP 去重。客户端不能通过 JSON 自行声明可信 IP。

## 汇总与详细统计

汇总模式保留当前每日全站 PV/UV、逐页 PV、来源聚合及事件去重，不保存原始 IP、User-Agent 或永久逐访问流水。

用户已同意先按建议实现详细模式：默认关闭，默认保留 168h。开启时在原有计数事务内增加一条详细事件，字段为服务端时间、event_id、page_id、当时的规范 URL/标题、解析后的客户端 IP、导航来源主机名、受长度限制的 User-Agent、当日访客摘要。每条是一个有效页面浏览事件，不记录每个 CSS/图片请求，不增加完整来源 URL 的查询参数采集。

明细展示将已有 UA 解释为浏览器、操作系统、设备类别，并保存 Accept-Language 的首选语言。解析失败显示未知，不影响计数，不增加浏览器端探测。首版不扩展为地理定位、UTM 归因、会话时长、滚动深度或点击追踪系统。

调研依据：[Plausible 设备、浏览器与操作系统](https://plausible.io/docs/devices)、[Matomo 默认采集数据](https://matomo.org/faq/general/faq_18254/)。分类取粗粒度名称，UA 无法可靠判断的版本或设备不补猜。

重复事件不新增详细行；数据写入失败不产生部分计数。关闭开关停止新增详细行，既有行按保留期清理；重新开启不补造过去的流水。修改保留期作用于现存详细行。汇总数据不随明细过期删除。

现有公开 JSON 继续只暴露允许公开的计数和热门文章，不加入 IP、UA、访客摘要或 Unlisted 明细。私有 HTML 先保留总览、每日趋势、来源、逐页统计，并在详细模式增加最近事件表；建议报告显示最多最近 1000 条并说明数据库中保留总数，数据库仍保存保留期内全部事件。首版不因此增加登录后台；用户可取回私有报告离线查看。最终展示结构结合本轮现有统计试用反馈确定。

默认主题在文章正文以及首页、分类、标签、归档、更新与分页列表的文章项显示同一稳定页面 ID 的累计阅读量，复用公开统计 JSON，一次获取后填充所有对应节点，不逐项请求 API 或查询数据库。启用统计的公开文章存在有效 0 计数时显示 0；统计关闭、未提供对应公开数字、请求失败时隐藏，不伪造 0。局部导航后列表也重新填充，个人明细不进入列表。近 30 天热门排序不改变累计阅读数口径。

## 发行包与升级

GitHub Actions 在版本标签触发后测试、编译、打包，再从压缩包解压到干净目录验收。发布平台按实际支持能力列明：Linux amd64/arm64 正式包，Windows amd64 预览包。提供 SHA-256 校验文件及许可文件。构建使用锁定依赖，个人输入、备份、数据库、密钥、旧站 Logo 不得进入包。

运行配置及内容展示配置带推荐默认值与填写注释。示例文章分别讲解快速开始、元数据与状态、附件、配置、升级，以及 Markdown/目录/代码/公式/Mermaid。日常写作模板保持短小；完整示例放在专门文章中。随包内容使用通用身份。

升级先停止进程，新包解压到新目录，迁移旧 config.yaml、content/ 和 data/ 后启动；新包不能覆盖这些用户文件。默认 templates/static 使用新版本；手工定制模板需自行合并，本轮不做通用主题更新管理器或在线自更新。校验首次启动、升级保留内容/密钥/统计、构建失败回退。

## 验收

最终验收使用实际发行包，运行环境不安装 Go、Node 或 Python。覆盖首次启动、内容更新、配置变更、反代真实 IP、浏览器统计、正文与列表阅读量、报告自动刷新、详细模式开关/清理、重启去重、备份恢复，以及公网无法取得私有文件。试用访问信息与用户真实生产统计分开保存。

按用户决定，不安排 Nginx 直读与统一服务的性能对照测试。保持预构建静态文件、合理缓存和连接复用，验证正常访问与后台任务并存即可。
